# Thaw

**The world gets warmer when you show up.**

Thaw is a real-world social adventure game. The map of wherever you are becomes a game board: public parks, libraries, squares, markets and public art turn into quest hubs. Accept a quest, walk there, check in, snap photo evidence, and earn XP plus an illustrated souvenir pin. Some quests are better with a party of 2–4, and every social quest has a solo option.

Built with React Native + Expo SDK 57 (expo 57.0.9, React Native 0.86, Expo Go), TypeScript (strict), React Navigation, Zustand, react-native-maps, expo-location, expo-image-picker, zod and react-native-svg. Accounts, parties, and saved progress use Supabase.

## Run it

You need Node.js 22.13 or newer. Use npm. `package-lock.json` is the source of truth.

```bash
cd thaw
npm install
cp .env.example .env
npx expo start
```

`EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are required. Without them the app stops on “Thaw isn’t connected.” Copy both from `.env.example`. They are public client values; row-level security protects the data. Never put the service-role key in this file.

After any `.env` change, restart with `npx expo start -c`.

Scan the QR code with **Expo Go** (SDK 57). If the phone and laptop are not on the same network, use `npx expo start --tunnel`. Email confirmation and password reset use the `thaw://` scheme (Expo Go uses `exp://`). Add `thaw://**` and `exp://**` to the Supabase redirect allow list.

A phone build that runs without this Mac is in [docs/thaw-native.md](../docs/thaw-native.md). That path is an Xcode archive to TestFlight, or a Gradle release APK. There is no `eas.json`. `ios/` and `android/` are generated by `npx expo prebuild` and gitignored. The app is not hosted on Vercel.

You can also review the UI in a browser with `npx expo start --web`. react-native-maps has no web support, so the browser shows an illustrated board of the same quest hubs (`GameMap.web.tsx`).

Expo is pinned at 57.0.9. `npx expo install --check` notes that 57.0.30 is a later SDK 57 patch.

## How a session works

1. **Intro.** Create an account or log in. There is no unsigned guest path.
2. **Onboarding**, then the tabs: Explore, Party, Collection, and You.
3. **Map.** Real play uses GPS. Hubs show state at a glance. The Nearby quests tray is the alternative to tapping pins.
4. **Quest.** Accept, walk there, and check in. Live check-in uses your GPS fix.
5. **Evidence.** Take or choose a photo and submit. A live reward requires a Gemini accept, then `recordLiveReward` calls the Supabase `complete_quest` function. The server computes XP. A simulated photo check does not write server XP.
6. **Pins and ranks.** Collection and the leaderboard read the signed-in cloud snapshot. Leaderboards are the global boards (`get_leaderboard`).

**Settings → Demo mode** stands in for GPS with a sample city (Seattle by default). Your account stays signed in. Parties stay on `SupabasePartyService`. Demo mode does not switch to the local simulated lobby, and it does not upload XP. Local `applyCompletion` runs only for demo-mode and example quests.

Settings shows the signed-in email, Supabase and Gemini status, sign out, and delete account. Delete account calls the `delete-account` edge function. **Reset demo** appears only in a development build while demo mode is on.

`PlayByTextScreen` is registered on the stack. Nothing in Settings or You navigates to it. Play by text still needs `EXPO_PUBLIC_PHOTON_API_URL` pointing at the Photon process, plus a signed-in session. See [photon/README.md](../photon/README.md).

## Where data lives

| What | Where |
| --- | --- |
| Accounts, profiles, XP, pins, daily XP, parties, chat | Cloud Supabase, from `supabase/migrations/` |
| Device cache of that progress, settings, and the active quest | AsyncStorage key `thaw-game-v3` |
| Place search cache | AsyncStorage keys `thaw-cache:*` |
| Auth session | AsyncStorage, via the Supabase client |

The client can update `profiles.display_name` and `profiles.avatar_hue`. Other game writes go through database functions (`complete_quest`, party RPCs, leaderboard RPCs). Apply `supabase/migrations/20261018000000_client_complete_quest.sql` on the live project or a signed-in Gemini accept cannot save XP. Whether that file is already applied was not re-checked from this repo.

## Configuration

Copy `.env.example` to `.env`. Placeholders (`YOUR_…_HERE`) count as unset. App env access for these names lives in `src/config/env.ts`. `EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_KEY` is read by `app.config.js`.

| Variable | Required | What it does |
| --- | --- | --- |
| `EXPO_PUBLIC_SUPABASE_URL` | Yes | Cloud project URL |
| `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Yes | Client key. Row-level security protects rows |
| `EXPO_PUBLIC_GEMINI_API_KEY` | No | Writes quests and checks photos. Without it, Thaw uses built-in quests and labels photo checks as simulated |
| `EXPO_PUBLIC_GEMINI_MODEL` | No | Default `gemini-3.5-flash-lite` |
| `EXPO_PUBLIC_PHOTON_API_URL` | No | Base URL of the Photon HTTP API for Play by text |
| `EXPO_PUBLIC_PHOTON_RELAY_URL` | No | If set, Share invite also POSTs `{ "message": "..." }` to `<relay>/invites` |
| `EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_KEY` | For Android release | Blank leaves the Android map blank. Restrict it to package `com.tbanerj.thaw`. iOS uses Apple Maps |
| `EXPO_PUBLIC_OVERPASS_URL` | No | OpenStreetMap Overpass endpoint for nearby places. Default is the public interpreter |

Anything prefixed `EXPO_PUBLIC_` is compiled into the app and can be extracted from a build. The Gemini key is still in the client. A backend proxy for that key is not in this repo.

## What's live

| Area | Behavior |
| --- | --- |
| Accounts | Email and password. Missing Supabase settings block the app |
| Places | GPS queries OpenStreetMap Overpass. Demo mode uses saved sample places |
| Quests | Gemini when the key is set; otherwise local templates. AI output is zod-checked |
| Photo check | Gemini when the key is set. A failed call or a missing key is a labeled simulated check and does not grant server XP |
| Parties | `SupabasePartyService`: invite codes, ready state, chat, Realtime. The simulated lobby class is not the store's active party service |
| Leaderboards | `get_leaderboard` / `get_my_rank` for the signed-in player |
| Play by text | Optional. The screen exists and is not linked from Settings or You |

## Architecture

```
App.tsx                      fonts, hydration gate, error boundary, navigation
src/
  config/env.ts              the only place app env vars are read
  theme/                     tokens, category and rarity styles
  types/                     domain types
  i18n/strings.ts            English UI strings
  data/                      demo regions, seeded places, demo people
  game/                      pure rules: progression, quest schema, local quests, leaderboard, geo
  services/                  gemini, cloud, auth, supabaseParty, messagingApi, places, location, storage
  services/supabase/         client and generated database types
  store/useGameStore.ts      Zustand + AsyncStorage; live rewards call complete_quest
  hooks/                     useAuthBootstrap, useWorld
  components/                Button, Paper, map/GameMap(.web).tsx, and the rest of the UI
  screens/                   Intro, Auth, Onboarding, Explore, quests, Party, PartyChat,
                             Collection, Leaderboard, Profile, Settings, EditAvatar, PlayByText
  navigation/                typed stack + tabs
```

Rewards for a real quest are granted in one place: the Supabase `complete_quest` function, called from `recordLiveReward` after Gemini accepts the photo. Demo and example quests use the local `applyCompletion` helper and stay on the device.
